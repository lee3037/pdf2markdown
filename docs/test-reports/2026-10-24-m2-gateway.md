## 58666 实例核实范围

- Mac 对目标主机 58666 的 `/openapi.json`、`/health` 只读请求未取得有效 HTTP 响应（curl 退出码 52）。用户给出的部署为 Windows 回环监听；Mac 的失败不能证明 Windows 本机服务未运行，也不能核实其实际契约。
- 原生异步请求/响应的开发依据仍为已核对 SHA-256 的官方 MinerU 3.1.1 安装包源码；这不等于实际实例已验通。
- 已交付 Windows 本机 `check-upstream.ps1` / `pure_gateway.probe`：只读实际 OpenAPI 和 health，检查上传字段、输出字段、异步路由、健康及精确版本；可以把实际 schema 保存到忽略的 `.local/`。不兼容时退出码 1，禁止继续假定兼容。
- 本机没有 Windows 远程执行通道；需要部署方在新目录完成预检和启动。没有修改 19091 或 58666 的监听、依赖、进程和远程文件，也没有向其提交 PDF。

## 本轮实现

- 独立 `gateway/` 子项目、Python 3.12 环境和 `uv.lock`；Windows setup 显式使用自己的 `.venv`，不在既有 Anaconda 环境安装包。
- 独立 Bearer token，所有 HTTP 入口先认证；有界请求体和 PDF 页数/大小检查，队列默认最多 4 个待完成任务。
- 仅接受本项目需要的原始 Markdown 和结构化 JSON 选项；固定回环上游，不转发网关 token，不跟随重定向，不接受客户端解析服务器/回调 URL。
- 单 Worker 串行处理、独立随机 ID 和 SQLite 映射、原始结果保留；进程文件锁防止重复 Worker。只允许自身任务查询，不直接暴露原生任务 ID。
- 上游 ID 持久化后可重启续查；暂时查询故障保持原任务。提交结果不确定或提交时崩溃则保护性停止新提交，需停止新网关并人工核实后解除保护；不会自动重传。
- 网页 Worker 对网关报告的 `submission_uncertain` 保留显式重提确认，不能点击普通重试静默重复上传。
- 引擎版本、上游接口指纹、网关 backend/命名空间参与客户端缓存隔离。
- 适配 OpenAPI 文件声明的 `format=binary` 和 `contentMediaType=application/octet-stream`；不将任意 JSON 字段视为文件上传。
- Windows 安装、只读预检、端口占用检查、启动、健康检查和本地恢复工具；随机密钥只写入忽略的配置。
- 显式公开文件清单打包部署 ZIP，并附 SHA-256 清单；CI 提供同名 artifact。没有打包 OMP 源码、密钥、虚拟环境、运行数据或模型。
